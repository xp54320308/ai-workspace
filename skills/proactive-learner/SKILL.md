# Proactive Learner

**让亚希主动出去找食吃，不只是等投喂**

## 核心能力

1. **定期外界探索** — 主动扫描 GitHub trending、AI 新闻
2. **自动发现** — 发现新的工具、项目、skill
3. **主动汇报** — 有价值的新发现及时告知用户
4. **知识沉淀** — 把学到的存到 memory/learned/

## 扫描频率

| 类型 | 频率 | 时机 |
|------|------|------|
| GitHub Trending | 每天 1 次 | 早间心跳时 |
| AI 新闻 | 每天 1 次 | 下午心跳时 |
| ClawhHub 新 Skill | 每 2 天 1 次 | 发现时随时汇报 |

## 探索来源

- GitHub Trending (AI/LLM category)
- ClawhHub (openclaw skills marketplace)
- Hacker News (AI/ML section)
- 各 AI 官方博客

## 汇报格式

### 发现汇报
```
🔍 新发现：[项目名]
- 亮点：[核心功能]
- Stars：[数量]
- 值得看吗？[是/否/待研究]
- 链接：[URL]
```

### 定期摘要（每天一次）
```
📊 今日外界动态
- GitHub Trending: [TOP 3]
- 新 Skill: [发现数]
- 值得关注: [1-2 个]
```

## 知识沉淀

发现的重要内容存入：
- `memory/learned/YYYY-MM-DD-learned.md`
- `memory/trends/YYYY-MM-DD-trending.md`

## 自动触发

在 HEARTBEAT 时：
1. 顺带检查是否有新的有价值发现
2. 如果有，汇报给用户
3. 如果没有，静默通过

## 行动准则

**宁可多报，不可漏报**
- 看到有趣的就记下来
- 不确定时就标记"待研究"
- 让用户决定是否深入

**主动 > 被动**
- 定期主动扫描
- 不要等用户问"有什么新东西吗"

## 反合理化表（Anti-Rationalization）

| 借口 | 现实 |
|------|------|
| "今天没什么新东西，跳过吧" | 没扫描 = 不知道有没有，不是真的没有 |
| "这个项目看起来太小，不值得记录" | 小项目可能是下一个爆款，记录让用户决定 |
| "上次扫过了，这次应该差不多" | 技术圈每天都在变，过期信息比没信息更危险 |
| "记个大概就行，不用存文件" | 没存文件 = 没学过。脑内记忆会丢失 |
| "主人没问，不用汇报" | 主动学习 ≠ 被动回答。有发现就该说 |
| "链接以后再记" | 链接是唯一证据，不记 = 丢了 |

## 验证清单（Verification）

每次扫描任务完成后，必须通过：

- [ ] 至少扫描了 1 个来源（GitHub/HN/ClawhHub）
- [ ] 发现已存储到 `memory/trends/` 或 `memory/learned/`
- [ ] 有值得汇报的内容已通知主人
- [ ] 每条记录包含：项目名、亮点、链接
- [ ] 无链接的发现标记为"待验证"

### 退出条件
**扫描 + 存储 + 汇报（如有价值）= 完成。只扫不存等于没扫。**

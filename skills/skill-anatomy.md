# Skill 解剖学 — OpenClaw Skill 编写规范

> 基于 [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills) 的设计哲学改造

## 核心理念

**Process, not prose** — Skill 是 Agent 要**遵循的工作流**，不是供阅读的参考文档。

---

## 标准结构

每个 `SKILL.md` 必须包含以下章节：

```yaml
---
name: lowercase-hyphen-name
description: 第三人称描述功能。Use when [触发条件]。
version: 1.0
---
```

### 1. Overview
一两句话说明这个 Skill 做什么、解决什么问题。

### 2. When to Use
- **触发条件**: 什么情况下使用
- **排除条件**: 什么情况下不用
- **示例**: 2-3 个具体场景

### 3. Core Process
分步工作流，带：
- 清晰的步骤编号
- 输入/输出说明
- 决策点（if/else）

### 4. Common Rationalizations ⭐ 必填
**反合理化表** — 列出 Agent 常见的偷懒借口和反驳。

```markdown
| 借口 | 现实 |
|------|------|
| "这个太简单，不需要走流程" | 简单任务更容易漏边界情况 |
| "我先做，验证以后补" | 没验证 = 没完成 |
```

**为什么重要**: AI 天然倾向于找理由跳步。这张表直接对抗"合理化"本能，显著提高 Skill 遵循率。

### 5. Verification ⭐ 必填
**验证清单** — 任务完成前必须通过的检查项。

```markdown
- [ ] 条件 1
- [ ] 条件 2
- [ ] 条件 3

### 退出条件
**全部 ✅ = 完成。"看起来对"永远不够。**
```

**为什么重要**: 没有验证标准的 Skill = Agent 自己判断完成 = 质量不可控。

### 6. Notes / Gotchas
可选，记录注意事项、边界情况、已知陷阱。

---

## 质量检查表

新建 Skill 前，对照这个表：

- [ ] 有明确的触发条件和排除条件
- [ ] 有分步工作流（不是散文描述）
- [ ] 有反合理化表（至少 3 条）
- [ ] 有验证清单（至少 3 项）
- [ ] 有退出条件（可验证的证据）
- [ ] 不含硬编码路径/密钥
- [ ] 跨平台兼容（Windows/Linux/macOS）

## 反合理化表模板

复制粘贴后修改：

```markdown
## 反合理化表（Anti-Rationalization）

| 借口 | 现实 |
|------|------|
| "这个太简单，不需要走流程" | 简单任务更容易漏边界情况 |
| "我先做，验证以后补" | 没验证 = 没完成 |
| "以前做过，直接复用" | 上下文可能变了，每次都要确认 |
| "记个大概就行" | 大概 = 不精确 = 出错 |
| "主人没问，不用汇报" | 主动 ≠ 被动，该说就说 |
```

## 验证清单模板

```markdown
## 验证清单（Verification）

- [ ] [具体检查项 1]
- [ ] [具体检查项 2]
- [ ] [具体检查项 3]
- [ ] 结果已记录/汇报

### 退出条件
**全部 ✅ = 完成。要有证据，不是感觉。**
```

---

## 设计哲学总结

1. **流程优先** — 明确步骤 > 模糊描述
2. **反合理化** — 堵死偷懒的路
3. **验证驱动** — 证据 > 感觉
4. **渐进披露** — 最小化 token 消耗
5. **可组合** — Skill 之间可以协作
